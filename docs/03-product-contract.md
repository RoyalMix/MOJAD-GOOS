# MOJAD PRODUCT CONTRACT™ v1.0

Status: DESIGN / FOUNDATION

## Principle
NO PRODUCT WITHOUT A CONTRACT.

A MOJAD product is:
Experience + Capability + Data + API + Security + Identity + Dependencies + Evidence + Operations.

## Required sections
1. Product identity
2. Purpose and users
3. User experience
4. Identity/authentication
5. Authorization
6. Capability dependencies
7. Inputs and outputs
8. API/error/event contracts
9. Data ownership and flow
10. AI configuration and permissions
11. Memory boundaries
12. Opportunity Engine integration
13. Trust/reputation
14. Economy/payment/Pi
15. Media/storage/realtime
16. Security and privacy
17. Environment
18. Testing
19. Monitoring
20. Release/rollback
21. Product-to-product integration
22. Evidence

## AI
Use MOJAD AI Router and provider adapters. Do not hardcode a strategic provider.
Permission levels: READ, SUGGEST, EXECUTE, SENSITIVE_EXECUTE.
Sensitive execution requires authorization and, where required, human confirmation.

## Memory
Memory must be user-scoped and permissioned. Separate session, conversation, user, product, knowledge, opportunity and system knowledge.

## Economy
Rewards and payments require a legitimate source/budget, eligibility rule, anti-abuse controls and evidence. No arbitrary token emission.

## Pi
Pi status must be explicit: NOT_CONNECTED, SANDBOX, TESTNET, PARTIAL, VERIFIED, PRODUCTION or BLOCKED. Market price must never be represented as protocol-defined Pi value without official evidence.

## Non-negotiables
No contract = no build.
No owner = no production.
No evidence = no verified claim.
Reuse before rebuild.
No fake data or fake Pi.
No secrets in source code/frontend/ordinary DB.
No duplicate authority.
No production migration from assumptions.
