# MOJAD GOOS — RUNTIME SOURCE OF TRUTH STANDARD™ v1.0

**Status:** Governance Standard

## Core Rule
**ONE ARCHITECTURE → ONE AUTHORITY PER DOMAIN → MANY WORKERS → EVIDENCE-BASED RUNTIME**

GitHub is canonical for code, contracts, architecture, migrations, tests, CI/CD, governance and documentation. Production systems/providers remain runtime systems and do not silently redefine MOJAD architecture.

## Worker Principle
ChatGPT, Copilot, Lovable, Bolt, Replit, Pi tools and other tools are workers/contributors. They may inspect, propose, implement approved changes, test and document. They may not independently redefine MOJAD architecture, financial authority, identity authority, trust authority or production security policy.

## Evidence States
Use only: VERIFIED-CODE, VERIFIED-DATABASE, VERIFIED-PROVIDER, VERIFIED-RUNTIME, BASELINE-REPORTED, PARTIAL, UNKNOWN, BLOCKED.

**Not found in GitHub ≠ absent in production.**  
**Reported ≠ verified.**  
**Documentation ≠ runtime evidence.**

## Duplicate-System Rule
Before creating a capability: search → identify owner → inspect contract → inspect implementation → verify runtime where relevant → reuse/adapt → only then create new authority with approval.

## Change Rule
**INSPECT → REUSE → EXTEND → TEST → VERIFY → DOCUMENT → APPROVE → RELEASE**

Never silently overwrite a runtime system or create a second authoritative implementation.

## Final Principle
**One MOJAD. One governance model. One authoritative architecture. Many interoperable capabilities.**
